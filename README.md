## 🌟 Key Features & Production Enhancements

- **Interactive User Onboarding**: Users submit their name to create an authenticated MongoDB user document before starting a session.
- **AI Support Persona (Kiara)**: Configured system prompt establishing Kiara as an empathetic, professional customer support agent.
- **Conversational Context Windowing**: Passes the last 10 historical conversation turns to Gemini API `model.startChat({ history })` for context-aware responses.
- **Optimistic UI Updates (RTK Query)**: User messages render immediately on the right side upon clicking send, with automatic rollback if network requests fail.
- **Custom React Portal Modals**: Replaced native browser alerts/confirms with custom backdrop-blurred dialogs (`ConfirmModal.jsx`).
- **Resilient AI Fallbacks**: Automated model candidate fallbacks (`gemini-2.5-flash`, `gemini-2.0-flash`, `gemini-1.5-flash-latest`) guaranteeing response stability.

## 📊 Data Schema & Design Rationale

### 1. `User` Schema (`Backend/models/User.js`)
```javascript
{
  name: { type: String, required: true, trim: true },
  createdAt: Date // Auto-generated by Mongoose { timestamps: true }
}
```

### 2. `Message` Schema (`Backend/models/Message.js`)
```javascript
{
  userId: { type: Schema.Types.ObjectId, ref: 'User', required: true },
  role: { type: String, enum: ['user', 'assistant'], required: true },
  content: { type: String, required: true, trim: true },
  createdAt: Date // Auto-generated by Mongoose { timestamps: true }
}
```

> **Design Choice Rationale**:
> We selected a 2-collection model (`User` and `Message`). Avoided creating a separate `Conversation` collection to prevent unnecessary schema complexity for single-session support chat. Every message references `userId` directly and indexed on `{ userId: 1, createdAt: 1 }` for high-performance history fetching.
>
> **How Timestamps Are Recorded**:
> Timestamps are managed automatically using Mongoose's `{ timestamps: true }` option. Mongoose records `createdAt` ISO timestamps upon document creation. History queries sort strictly by `createdAt: 1` ascending (`Message.find({ userId }).sort({ createdAt: 1 })`).

## 🤖 AI Provider Details & System Prompt

- **Provider**: Google Gemini API
- **Models Used**: `gemini-2.5-flash` (Primary), `gemini-2.0-flash` (Fallback)
- **SDK**: `@google/generative-ai`
- **System Persona**:
  > *"You are Kiara, a professional, empathetic, intelligent, and concise AI Customer Support Assistant. Your primary role is to assist users with their inquiries, provide clear solutions, and maintain a warm, confident, and polite tone."*
- **Context Handling**: Last 10 conversation messages are formatted into `{ role: 'user' | 'model', parts: [{ text }] }` and passed into `model.startChat({ history })`.

## 🚀 Setup & Installation Instructions

### Prerequisites
- Node.js (v18 or higher)
- npm / npx
- MongoDB Atlas connection URI
- Google Gemini API Key

---

### Step 1: Backend Setup

1. Navigate to the `Backend` directory:
   ```bash
   cd Backend
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Create your `.env` file (refer to `.env.example`):
   ```env
   PORT=5000
   NODE_ENV=development
   MONGODB_URI= ''
   GEMINI_API_KEY=your_actual_gemini_api_key
   ```

4. Start the backend server:
   ```bash
   npm run dev
   ```
   *The backend will start on `http://localhost:5000`.*

---

### Step 2: Frontend Setup

1. Open a new terminal and navigate to the `Frontend` directory:
   ```bash
   cd Frontend
   ```

2. Install dependencies:
   ```bash
   npm install
   ```

3. Create your `.env` file (refer to `.env.example`):
   ```env
   VITE_API_BASE_URL=/api
   ```

4. Start the Vite dev server:
   ```bash
   npm run dev
   ```
   *The frontend will start on `http://localhost:3000`.*

## 🔌 API Endpoints Reference

| Method | Endpoint | Description | Request Body / Params |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/users` | Create user document | `{ "name": "User" }` |
| `POST` | `/api/chat` | Send message & receive AI reply | `{ "userId": "<id>", "message": "Hello" }` |
| `GET` | `/api/chat/history/:userId` | Fetch full user conversation history | `userId` in params |
| `DELETE` | `/api/chat/history/:id` | Delete a single message by ID | `id` in params |
| `GET` | `/api/health` | Backend status health check | *None* |
